# Image editor testing: isolated sources and direct ADB

**Implemented runner; root verified 26/26 direct native/Android cases at `ac41edf`
and 28 actual service/native/Compose methods at `3310a26` on OnePlus LE2125/API 36.
Broader accessibility/API/16 KiB runtime coverage remains followup work.**
`scenarios.json` declares 36 acceptance cases. Direct `all` selects exactly 26
native/Android cases; eight host cases, one release artifact gate and one explicit no-native case run separately.
The runner is opt-in: ordinary no-argument test discovery skips it, while any
explicit unknown/native request fails strictly. No-native is never a fallback.

## Isolation and source layout

Keep production image contracts/rendering in the normal app/core/engine modules.
Tests call those classes rather than implement another editor or encoder.

```text
testing/image/
  README.md                     # test contract
  scenarios.json                # implemented acceptance declarations
  core/dev/forma/core/image/     # JVM model/planner/fit tests
  engine/dev/forma/ffmpeg/image/ # probe/prepare verification tests
  app/dev/forma/app/image/       # JVM persistence/queue tests
  android/dev/forma/app/image/   # instrumentation, fixtures and reports
```

Add these directories only to Gradle **test/androidTest** source sets. Test-only
JUnit/AndroidX dependencies never become implementation dependencies. Use the
existing debug target plus separate instrumentation APK; do not add a production
receiver, exported test service, web server or raw FFmpeg command endpoint.
Reconcile existing testing switches from other PRs rather than replace their
source sets. `imageTests=false` removes only this image workstream's references.

Fixtures are small synthetic patterns generated by Kotlin inside the test APK:
corner labels, asymmetric colored grids, gradients, transparent edges, noisy
images, Unicode labels and EXIF orientation variants. Use a test-only bounded
header builder for malformed files. No private photographs, large binaries or
native downloads are committed. Advanced color/format fixtures need provenance
and a separate capability gate before B/C qualification.

Expected geometry/pixels must come from an independent known-answer oracle, not
from calling the production planner twice. Full decode and native artifacts are
required for pixel tests. Header inspection alone cannot prove correct pixels.

## Build and install

Use the repository's source-built FFmpeg bundle and its existing native verifier.
Do not replace it with an API-only AAR. Use the separately built image-capable Maven bundle described in `docs/ffmpeg.md`,
including Android zlib and libwebp. In this workspace source `vendor/tooling/env.sh`
and set `NATIVE_REPO="$FORMA_ROOT/local-native-image"`; retain the graphics-path
repository flag. The lab suffix isolates user data from other queue schemas.

```bash
./gradlew -PformaLab=true -PffmpegEnabled=true -PffmpegRepo="$NATIVE_REPO" -PimageTests=true \
  -PgraphicsPathRepo="$FORMA_ROOT/vendor/graphics-path/maven" \
  :core:test :engine-ffmpeg:testDebugUnitTest :app:testDebugUnitTest \
  :app:assembleDebug :app:assembleDebugAndroidTest :app:lintDebug
adb -s "$SERIAL" install -r app/build/outputs/apk/debug/app-debug.apk
adb -s "$SERIAL" install -r app/build/outputs/apk/androidTest/debug/app-debug-androidTest.apk
adb -s "$SERIAL" shell pm list instrumentation
```

Resolve actual application/test package names from the built APK/manifest.
The opt-in lab target is `dev.forma.transcode.lab`, instrumentation package
`dev.forma.transcode.lab.test`; release keeps the normal application ID.
Install matching revisions together and record hashes of the actual installed
base APK and any splits. The host's `git rev-parse HEAD` is a declared revision,
not proof of installed APK identity.

## Direct ADB scenario interface

Arguments: `formaImageCase`, canonical UUID `formaImageRunId`, and
`formaDeclaredRevision` (diagnostic only). `all` selects every manifest case whose
`runOn` is `android` or `native`; it does not run host/artifact cases.
`no-native` cases run explicitly on a no-native build, never as part of `all`.
Unknown/unsupported case IDs, wrong argument types and reused UUIDs fail.
There is no arbitrary command/path/expression execution argument.

Bash, after building the described runner:

```bash
RUN_ID="$(uuidgen | tr '[:upper:]' '[:lower:]')"
REVISION="$(git rev-parse HEAD)"
adb -s "$SERIAL" shell am instrument -w -r \
  -e class dev.forma.app.image.ImageEditorScenarioTest \
  -e formaImageCase all \
  -e formaImageRunId "$RUN_ID" \
  -e formaDeclaredRevision "$REVISION" \
  dev.forma.transcode.lab.test/androidx.test.runner.AndroidJUnitRunner
adb -s "$SERIAL" exec-out run-as dev.forma.transcode.lab \
  cat "files/image-tests/$RUN_ID/report.json" > "image-$RUN_ID.json"
```

PowerShell equivalent:

```powershell
$runId = [guid]::NewGuid().ToString()
$revision = (git rev-parse HEAD).Trim()
```

## Required report contract

Write a new run directory atomically and refuse overwriting a prior UUID. Reports
use schema 1 and include the run ID, selected case IDs, requested selection,
positive selected/executed/passed counts, status, start/end monotonic timings and
per-case results. An expected rejection is a passing test only when the declared
error code and no-publication behavior were actually observed.

Also record source commit as declared metadata; actual installed APK/split hashes;
FFmpeg version/configuration/build identity; device model/API/ABI/page size;
source fixture hash; document/recipe hash; effective format/encoder/filter route;
argument tokens with source-identifying paths redacted; candidate dimensions,
alpha/color/metadata facts; exact bytes; decoded-output checks; cancellation and
publication state; memory/thermal observations where available.

Separate `expectedOutcome`, `observedOutcome` and `assertionsPassed`. Do not count
an app returning any error as a successful rejection test. A report with status
PASS must have every selected case executed and passed with no skipped cases.

The caller must require **both** successful instrumentation with at least one
completed test and a matching fresh report with exact expected case coverage.
ADB process exit alone is insufficient. Verify run ID and installed artifact
identity; never consume a fixed-name report left by a previous run. Read back the
written report before announcing PASS. Attach outputs/evidence to the code PR,
not generated test-suite source commits.

## Test matrix

[scenarios.json](scenarios.json) is the machine-readable acceptance index.
The implementation must supplement it with each task's focused unit/UI tests.

| Gate | Required proof |
| --- | --- |
| Host core | Validation, overflow, crop math, neutral graph, immutable snapshots, retry count and exact byte boundaries. |
| JVM adapters | Strict persisted-document/queue migration, corrupt-data preservation, stale revisions and error classification. |
| Emulator | Real Compose controls, touch size, large text, state preservation, accessibility, URI/storage and stale preview behavior. |
| Native packaging | Real .so payload, matching ABI, native build identity and alignment; an API contract AAR is insufficient. |
| Physical output | Full decode, known geometry/pixels/alpha, EXIF orientation, metadata removal, real size-fit and source preservation. |
| Lifecycle | Stop during prepare/encode/verify, process recreation, revoked URI, low disk/memory and no partial publication. |
| Release exclusion | Build without image-test sources and inspect shipped dependencies/dex/assets/manifest. |

Test the user's available OnePlus device and an independent Android vendor when
available; do not assume a connected device or vendor-wide compatibility from a
single handset. Cover API 26/27 fallback and API 28+ image APIs, plus actual 16 KB
page-size native execution separately. Emulators can cover API/UI behavior, not
establish physical-phone speed or NPU execution.

For lossy exports, define explicit codec/color tolerances and retain decoded
comparisons; equal quality slider numbers do not establish equal quality. No
speedup claim without repeated same-input/same-output-quality measurements and
recorded thermal/memory conditions. This branch runs no benchmarks.

## Product-only removal proof

In a disposable checkout, move/remove `testing/image/`, then build:

```bash
./gradlew -PimageTests=false -PffmpegEnabled=true -PffmpegRepo="$NATIVE_REPO" \
  :app:assembleRelease
```

A release native-payload/signing requirement still applies. Inspect release dex,
assets, dependencies and manifest for absence of scenario/fixture/report classes
and test entry points. Confirm normal image export still works. Only the image
source-reference switch changes; other workstreams' tests remain governed by
their own documented switches. Do not delete product rendering code to remove
tests or claim exclusion merely because an instrumentation APK is separate.
