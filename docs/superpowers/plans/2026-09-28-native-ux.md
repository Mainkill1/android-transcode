# Native responsiveness and UX implementation plan

Goal: simplify the existing native workflow while keeping editing, imports and
foreground conversion independently responsive. FFmpeg remains the export owner.
Baseline: e6fb225983ef0a9972b5fd87fd9c219597702005. Direct main updates requested.

1. Test bounded progress publication, finite progress math, FFmpeg thread budgets,
   process-wide exclusive run ownership, drain-after-current and cancellation
   cleanup races. Implement Android-free policies and coroutine runtime helpers.
2. Integrate the helpers into AppGraph and the foreground service. Serialise native
   calls and cache capability discovery. Expose queue control independently of
   ViewModel busy work. Cancel on service destruction and timeout, retain the slot
   until native cleanup really completes; persist queue transitions, not every tick.
3. Split file operations from queue mutations. Add import/save progress and cancel,
   move provider calls and validation off Main, prevent duplicate enqueue, preserve
   editing. Keep cancellation distinct from failure. Repair initialization retry.
4. Replace the crowded native screen with source-first Compose, a left shelf,
   separate lazy queue, sticky activity indicator, contextual advanced controls,
   accessible choices and clear waiting/stopping/completed/failed states. Read
   progress only inside its small composable, not at the root.
5. Add deterministic regression tests, Compose behavior/recomposition tests and
   device benchmark instructions. Run host checks and Android CI, record actual
   evidence. Do not call host/emulator tests physical FFmpeg performance proof.

Not this change: complete native upload-fit/URL/image/editor parity, NPU/GPU
inference, arbitrary native thread-pool tuning, automatic resurrection after force
stop. Preserve the existing native-port handoff. No scheduled automations.
