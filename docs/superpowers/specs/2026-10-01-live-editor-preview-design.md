# In-app editor and near-live visual preview

## Intent and boundary

The user should be able to rotate or crop selected media and see the result while editing, without opening another app or waiting for a full conversion. One obvious **Edit** action opens a focused editor with the preview always visible. The control labels describe their actions; technical settings stay in a secondary panel. A fast source-frame visualization is distinct from a verified rendered preview. The original and already queued jobs remain unchanged until the user explicitly queues a new immutable edit snapshot.

This work reuses `ClipEffects`, `ImageEditDocument`, `ImageCanvas`, the existing foreground `RunCoordinator`, and `FfmpegRenderSession`. It does not introduce another encoder, claim GPU filtering, or replace FFmpeg export. The following precision-timeline work uses the same editor shell and preview state.

## Screen and interaction

From a selected image or video, **Edit** opens a full-screen native workspace. The top pane fits the preview within the available display without hiding crop handles. A small status identifies `Quick frame`, `Updating frame`, `Rendered preview`, or a specific preview error. The primary bottom tools are **Trim**, **Crop**, **Rotate**, and **Play preview** for video, with image-appropriate tools for a still. Undo, Redo, Reset, and Export remain reachable without scrolling through all advanced encoding settings. A source switch or Back preserves a valid draft; leaving with unsaved edits offers Keep editing, Save draft, or Discard. A new versioned editor-draft record stores the selected source identity, current tool, and validated edit commands; recovery after rotation or process recreation restores the latest committed draft, never an in-progress pointer gesture. If the source grant has expired, the editor asks the user to reselect it before preview or export.

The image canvas opens as the editor's default view instead of requiring a second **Edit image** tap. Dragging crop corners moves the visible crop boundary and masks the removed area immediately. Tapping Rotate changes the displayed orientation immediately. The native edited image preview continues to render asynchronously; while it catches up, the canvas says `Quick preview · updating` rather than showing an old bitmap as if it were current. The existing full-resolution/100% controls and input-memory limits remain.

For video, the editor shows a decoded still at the playhead. Crop exposes draggable corner/edge handles over this frame and keeps the existing even-pixel/export validation; the user can also enter exact coordinates. Rotation and flips transform the frame instantly on the Compose side. A draft changes only visual state during a gesture; release validates and commits one `ClipEffects` command to undo history. Cancel restores the previous effect. The source's orientation metadata is mapped into the same canonical crop coordinates used by export; if a source's display matrix cannot be mapped safely, crop is disabled with a reason instead of previewing a different rectangle from the one FFmpeg would export. Brightness and other existing effects can retain their current controls, but their quick visualization must be labeled approximate until the rendered preview is ready.

**Play preview** renders a bounded five-second window around the current playhead, clipped to the selected kept range, using the existing FFmpeg path and current immutable edit snapshot. It plays inside Forma using Media3 and does not become a Finished conversion or get auto-saved to public media. **Preview full movie** retains the existing whole-movie render in the movie workspace; the precision-timeline work connects the short preview to the composed sequence and transitions. A stale preview is visibly marked after any edit and cannot replace a newer revision. Preview files are private, bounded, and cleaned when superseded or on startup. Full export still goes through the foreground service's strict validation and publication.

## Preview ownership and responsiveness

A single Android `MediaMetadataRetriever` per active video source decodes a scaled frame at the requested time on a bounded IO dispatcher. API 27+ uses scaled extraction; API 26 downsamples the returned frame before publication and enforces the same bitmap budget. Cache only the active full preview frame and a small fixed set of nearby thumbnails. A fast crop/rotation drag transforms the already cached frame on the UI thread; it does not enqueue FFmpeg work for every pointer sample. Source switch, new seek, or revision change invalidates obsolete decode results. Frame extraction returns the nearest decodable frame, so the UI displays the requested time and says `Quick frame` rather than asserting frame-exact source decoding. If extraction is unavailable, show an honest error and preserve numeric editing and rendered preview access.

The quick frame path may refresh while conversion runs only within its memory/decoder budget. An expensive FFmpeg rendered preview waits for the process-wide native run slot; it never overlaps a foreground encode or releases staged files before cancellation cleanup. The user can keep interacting with the cached frame while it waits. Media3 playback owns and releases its player with the screen lifecycle, keeps audio focus behavior explicit, and never mutates the edit graph when seeking or playing.

## Correctness and acceptance

Share a single pure geometry mapper between the quick-frame overlay and `ClipEffects` export planning. Test landscape, portrait metadata, 90/180/270-degree turns, flips, edge crops, odd source sizes, cancellation, and crop rejection. Quick preview is navigation feedback; it must not be used as evidence that a final file decoded or met the byte cap. Compare a rendered preview frame and exported frame for crop/rotation geometry on the target device; separately verify the export's existing strict decode/count path. The phone check should record gesture-to-visible-transform latency with a cached frame (target p95 at or below 150 ms), frame refresh latency, memory use, and behavior while a conversion occupies the native slot. A missed latency target requires iteration or a clearly stated limit, not a performance claim.

Write failing core geometry/history tests before changing the model, Compose tests before routing/control changes, and an Android frame-controller test before decoder code. Exercise image and video imports, edit/undo/redo, rotation, Back, process recreation, large text, touch targets, and in-app playback on the OnePlus. Run host core/readiness checks, Gradle unit/build/lint, emulator Compose checks, and the relevant physical source/preview/export suite. The quick-frame path may have different color appearance from final native output, especially for HDR; the interface must say when rendered color is not available rather than claiming color grading parity.
